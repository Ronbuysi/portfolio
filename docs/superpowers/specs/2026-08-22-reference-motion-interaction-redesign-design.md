# 参考站点交互与动效重构设计说明

## 1. 目标

在保留王程程作品集现有黑底、暖白、荧光黄和完整作品内容的前提下，学习 [moncy.dev](https://www.moncy.dev/) 的交互与动效机制，把页面从“多个组件各自运动”重构为一条可理解的滚动叙事：进入页面、认识设计师、浏览作品、进入案例、继续浏览下一个案例。

本轮的主目标不是复制参考站点的 3D 角色、文案或视觉风格，而是吸收以下机制：滚动绑定动画、固定章节、横向作品轨道、逐级文字揭示、上下文 Cursor、项目转场和移动端降级。

## 2. 当前实现诊断

当前站点已经有 Hero、预加载、固定导航、Cursor、滚动进度、视差、作品环、全屏项目详情和六套 Story 组件，内容完整度较高。浏览器检查发现 `WorkRing.jsx` 在进入作品区后抛出 `ReferenceError: AUTO_SPEED is not defined`，导致自动旋转循环中断；现有 Vitest 108 项测试通过，但尚未覆盖这一类真实浏览器运行错误。

当前动效还存在三个结构问题：

1. `useRevealOnScroll`、`useParallax`、`Cursor` 和 `WorkRing` 各自维护动画循环，没有统一的 motion profile 和生命周期管理。
2. 作品环需要用户理解拖拽和旋转规则；它有视觉冲击，但不如“垂直滚动驱动横向作品轨道”直观。
3. `ProjectDetail` 以全屏覆盖层打开，缺少从项目卡片到案例标题、封面和章节的连续转场，也缺少焦点恢复与进入来源管理。

## 3. 参考站点的可迁移机制

公开页面与运行状态显示，参考站点使用 Three.js Canvas 作为 Hero 交互载体，使用 GSAP、ScrollTrigger 和 SplitText 类机制完成滚动动画；Work 区使用 `pin: true`、`scrub` 和横向 `x` 位移，把一段普通的垂直滚动转成固定视口内的横向作品浏览。其 Cursor 会在普通状态、社交图标状态和作品链接状态间切换，文字通过逐字符或逐词的轻量延迟进入。

迁移到本作品集时只保留对作品浏览有帮助的部分：

- Hero 使用已有视频和鼠标轻微位移，不引入 3D 角色。
- 作品区使用固定视口横向轨道，不再自动高速旋转。
- 项目详情使用阶段式进入，不使用重型共享元素动画依赖。
- 动效只改变 `transform`、`opacity`、`clip-path` 和少量颜色，不改变作品本身。

## 4. 目标浏览路径

### 4.1 Hero：从身份进入

首屏保持全屏视频。用户向下滚动时：

1. 主标题以整体位移和透明度退出，背景视频轻微放大并降低亮度。
2. 副标题和身份标签按行进入 About 的上沿。
3. 页面进度线从 Hero 进度过渡到作品浏览进度。
4. 桌面端保留最多 8px 的鼠标跟随位移；触摸设备不启用。

### 4.2 Project Rail：从垂直滚动进入横向浏览

作品区使用桌面端 `pin + scrub`：

- 轨道固定在视口内，滚动距离由卡片总宽度计算。
- 轨道横向移动，垂直滚轮仍然是唯一输入，不劫持滚动。
- 当前项目编号、标题和分类随 ScrollTrigger 的 progress 更新。
- 当前卡片有荧光黄边线和可见标签；其他卡片降低透明度但保持可识别。
- 每张卡片支持鼠标、键盘焦点和 Enter 打开详情。
- 移动端取消 pin 和横向 scrub，改为单列卡片，每张卡片使用 clip reveal。

### 4.3 项目进入：从卡片进入案例

打开项目时，保存触发卡片的 `getBoundingClientRect()` 和触发元素引用：

1. 背景从透明变为深黑。
2. 项目详情从触发卡片的区域扩展到全屏，鼠标触发使用 clip-path；键盘触发使用 fade-up 备用方案。
3. 顶部项目栏先进入，随后编号、标题、元数据和封面按 80ms 错峰出现。
4. 详情关闭后恢复原滚动位置，并将焦点放回触发卡片。

### 4.4 案例内部：章节推进

每个 Story 组件只注册一个章节状态源，媒体和文字根据章节 progress 进入；不为每一张图片创建独立 RAF。大图使用 clip reveal，辅助图使用淡入和 1.02 倍以内的缩放，移动端关闭视差。

## 5. 六个作品的专属动效

### 001 运营视觉设计 / `market-route`

把“逛市场”变成横向路线。首张海报从左侧进入，第二、第三张海报以轻微上下错位跟随；`BRUSH MARK`、`CUTOUT COLLAGE`、`HALFTONE GRAIN` 和 `SIGNAL COLOR` 四个视觉语法卡按路线顺序点亮。原创系统图片用连续 clip reveal，摊位、导视、摊主工具包和集章护照四组延展按“现场入口 → 服务工具 → 参与机制”顺序出现。悬停卡片显示路线箭头，不改变图片裁切。

### 002 生活新搭案 / `three-phase`

用一个固定的三阶段滚动轨道表达“亮、合、暖”。滚动 progress 映射到三个节点：`LIGHT` 使用黄色、`CONNECT` 使用粉色、`WARM` 使用紫色；当前阶段卡片上移并提高不透明度，其他阶段缩小到 0.96。视觉语法区的拼图元素使用节点连线动画，原创海报依次进入，线下活动、礼赠和数字传播作为三组横向应用带出现。移动端改为三个可点击的手风琴章节。

### 003 成长日常 / `timeline-swap`

以“小时候 / 长大后”的双联画为主交互。桌面端固定两张作品，滚动通过遮罩和物件层的透明度完成替换；时间轴指示器从 `CHILDHOOD` 过渡到 `GROWN-UP`。产品保持稳定位置，玩具、画笔、电脑、报表等物件按同一坐标淡入淡出，突出项目概念而不是制造无意义旋转。移动端上下排列两张海报并使用普通揭示。

### 004 倒倒 bar / `pour-at-eleven`

以 11 PM 为时间锚点。进入案例时显示一个缓慢旋转的时间刻度；滚动 progress 驱动瓶身倾角、酒液方向和空间灯光强度，幅度控制在 3–6 度。品牌概念四卡按 `LAZY → PAUSE → RELAX → IDLE` 依次进入；身份规则四卡使用“角色、倾倒、容器、时间”四个 hover 状态。空间、会员、夜间传播、导视和外带系统采用低频左右交替进入，避免酒吧项目变成高频霓虹特效。

### 005 MY MAY / `pause-and-warm`

把“街角暂停键”转译成交互语气。门店 Hero 缓慢呼吸，指针进入作品媒体时，局部动画减速并出现暖橙光晕；离开后恢复。品牌 DNA 的 `PAUSE / PIZZA / PAWS` 三个词与色板在滚动时逐个点亮。团队、数字传播、门店、外带和城市触点五组延展采用从中心向外的轻量扩散，不做弹跳。移动端只保留触摸后的短暂高亮。

### 006 TOSS DIARY / `character-keyframes`

把角色动作当作滚动关键帧。根据已有的角色、服务、夏日活动、表情和季节资产，滚动时依次展示“制作、取餐、奔跑、分享、四季、聊天”六个状态；每个状态只使用一个主媒体和一个文字说明。表情系统支持 hover/focus 切换，桌面端使用 120–180ms 的小幅弹性，移动端改为点击切换。不得为每个表情建立独立动画循环。

## 6. 技术架构

- 新增 `gsap` 与 `@gsap/react`，使用 `useGSAP` 或 `gsap.context()` 确保 React 卸载时清理 ScrollTrigger 和动画。
- 新增 `src/motion/motionProfiles.js`，以数据描述六个作品的模式、颜色、章节和移动端策略。
- 新增 `src/hooks/useScrollTimeline.js`，封装 desktop pin、scrub、resize refresh 和 reduced-motion 分支。
- 新增 `src/components/ProjectRail.jsx`，替换 `WorkRing` 的主入口；旧 `WorkRing` 在引用移除并通过测试后删除。
- 保留 `useRevealOnScroll` 作为普通内容的降级揭示，但不再让它与案例主时间轴重复控制同一节点。
- 扩展 `Cursor` 为 `default / view / drag / close` 四种状态，并通过 `data-cursor` 声明交互意图。
- `ProjectDetail` 增加触发源、焦点恢复、转场状态和 Escape 处理；滚动锁定必须带滚动条补偿，避免页面横向跳动。
- 不引入 Lenis 或自定义滚动容器，不使用滚动劫持；不新增图片，不重绘作品。

## 7. 响应式、无障碍与性能

- `min-width: 1024px`：启用 pin、scrub、横向轨道和轻微鼠标位移。
- `768px–1023px`：保留横向卡片轨道但不 pin，使用普通横向滚动容器和明确的左右按钮。
- `<768px`：全部改为纵向流，不使用固定侧栏、横向 scrub、Cursor 和视差。
- `prefers-reduced-motion: reduce`：不播放自动 Hero 视频，不执行位移、旋转、clip reveal 和逐字错峰，内容立即可读。
- 所有项目卡片必须有可见 focus ring、Enter 打开、Escape 关闭和可读的 `aria-current`。
- ScrollTrigger 的每帧更新只修改 transform、opacity 和 CSS custom properties；图片使用固定比例容器，避免布局跳动。

## 8. 验收标准

1. `pnpm test` 全部通过，且新增 motion profile、ProjectRail、项目转场和 reduced-motion 测试。
2. `pnpm build` 成功。
3. 访问 `http://localhost:5173/?motion=force` 时浏览器控制台无 `AUTO_SPEED`、ScrollTrigger、ResizeObserver 或未捕获 Promise 错误。
4. 1440×1000 视口中，Hero 向 About、About 向作品轨道、卡片向项目详情均有连续转场。
5. 作品区通过普通垂直滚动完成横向浏览，用户不需要猜测拖拽操作。
6. 六个项目都能通过鼠标、键盘和触摸打开；每个项目都具有上文指定的专属动效。
7. 390×844 视口无横向溢出、文字遮挡或无法关闭的固定层。
8. reduced-motion 模式下所有项目仍完整可读，且不依赖动画完成内容展示。

## 9. 非目标

- 不复制 moncy.dev 的 3D 角色、颜色、文案、布局或作品内容。
- 不把六个项目改成六个独立站点。
- 不新增 CMS、登录、表单、支付或外部数据服务。
- 不重新生成或替换用户现有作品素材。
